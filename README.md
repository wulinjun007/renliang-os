# 人粮 OS · 7 天批量备餐系统 — V0.1 原型

依据《人粮 OS PRD V0.1》实现的单文件 Web 原型，覆盖 PRD §20 规定的全部 8 个首版页面，演示闭环可完整跑通。

## 打开方式

直接双击 `index.html` 即可（无外部依赖、无构建）。数据保存在浏览器 localStorage，不上传服务器。

## 8 个页面 ↔ PRD 对照

| PRD 页面 | 路由 | 内容 |
|---|---|---|
| 01 Onboarding | `#onboarding` | 目标输入（热量/蛋白/餐数/预算）→ 食材勾选 → 生成第一周 |
| 02 今天 | `#today` | 下一餐大卡 + 复热/调味 + 「吃掉了」+ 今日热量/蛋白进度 |
| 03 生成一周计划 | `#generate` | 三步向导 + AI 指令胶囊（换蛋白/降预算/生成下周） |
| 04 一周计划 | `#week` | 7×3 日历网格，点击任意餐可调份量/换蛋白 |
| 05 购物清单 | `#shopping` | 整周食材聚合 + 10% 损耗开关 + 预算对比 + 已买勾选 |
| 06 周末备餐 | `#prep` | **食材维度**任务卡（非菜谱维度）+ 步骤勾选 + 装盒预览（模式 A/B） |
| 07 冰箱库存 | `#fridge` | 冷藏/冷冻/常温分区 + 制作日期/保质期/剩余份数 + 吃掉一份 |
| 08 设置 | `#settings` | 身体目标/食材偏好/厨具/数据导出与重置 |

## 演示闭环（PRD §09）

生成计划（F03，热量/蛋白质对齐算法）→ 采购聚合（F04，+10% 损耗）→ 批量备餐任务（F05，含 Task 01 鸡胸/Task 02 西兰花等 PRD 示例）→ 分装模式 A 装盒 / B 散装（F06）→ 一键入库（冷藏 Day1-3 / 冷冻 Day4-7，F07）→ 今天「吃掉了」自动扣库存并更新当日营养（Step 9）。

首次访问建议点「跳过配置 · 直接体验演示数据」：预载本周计划 + 备餐 5/13 + 冰箱在库 + 早餐已吃。

## 设计语言

**GL-079 PIE（Just Eat Takeaway Design System）**，选自桌面库《网站设计规范 md/全球/GL-079-PIE-design-system.md》。选型理由：247 站库中唯一「食物原生」的深度提取规范——token 全量暴露（复刻可行性最高档），且 truffle/tomato/mozzarella 食物命名色族与本项目定位天然契合。

落地的 token（全部取自提取规范）：

- 底色 truffle-20 `#F0ECE6` / truffle-10 `#F6F3EF` / truffle-30 `#E7E2DA`；白卡 r12 + 8% 黑细线
- 行动橙 `#F36805`（仅 CTA/斜切色带/选中态）、番茄 `#F75E28`、链接蓝 `#3147AD`、绿 `#2B7836`、红 `#D60E0A`
- 字阶 48/900·32/900·24/800·16·14·12（JetSansDigital 为商用字体，替换为 PingFang SC 系统栈）
- 4pt 间距栅格（4/8/12/16/24/32/40/56/64/80）、胶囊 r50rem、海拔阴影 ≤8% 黑多层
- hover 仅底色换档（白→truffle-20）、动效 100-350ms + PIE 双缓动曲线
- 品牌签名：对角斜切橙色色带（onboarding 分区）

派生说明：berry/latte/cupcake/aubergine 四族在提取文档中未暴露 HEX，按族名气质派生（`#A62639`/`#B08968`/`#7A8B99`/`#3D2C3E`），已在 CSS 注释标明。

## 已知边界（诚实声明）

- 两餐/四餐制、条码扫描、AI 菜谱等按 PRD 划入 P1，未实现；餐数选项在 UI 中禁用并注明
- 数据模型为演示级（13 种食材），营养数字由 PRD 公共数据估算；预算超支时给出真实超支额与 AI 换蛋白建议，不伪造达标
- PRD §22 的食材处理数据库等长期资产仅在冰箱页以「保存策略」形式露出
